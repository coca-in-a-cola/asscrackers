# Реализация, проверки и приёмка (архив v2)

Источники требований: [PRD](../PRD.MD), [спецификация](mvp-spec.md). Этот документ сохраняет план и критерии приёмки. Реализация MVP выполнена; фактические проверки и оставшиеся пункты человеческого плейтеста перечислены в [отчёте](verification.md). Чекбоксы ручной приёмки ниже не подменяются автоматическими проверками.

## 1. Рабочий порядок агента

1. Прочитать требования, локальные инструкции, git status и актуальное состояние проекта.
2. Проверить установленный Godot и доступные инструменты. Сохранить существующие настройки и чужие изменения. Не создавать проект заново.
3. В индексированном проекте использовать CodeGraph для поиска существующего кода. Если кода ещё нет, не выдумывать зависимости.
4. Реализовывать последовательные рабочие срезы ниже. После каждого проверять изменённую функциональность.
5. Изменение нормативного поведения оформлять изменением спецификации; крупные изменения цели/scope согласовывать с владельцем.
6. Перед сдачей пройти автоматические и ручные проверки. Сообщить выполненное, команды проверки, результаты и оставшиеся ограничения.

Не зависеть от конкретной модели, MCP-сервера или IDE. Если инструмента нет, использовать доступный редактор файлов и Godot CLI. Не заявлять о снятии скриншота, запуске или успешных тестах, если этого не было.

## 2. Этапы

### A. Вертикальный срез: от досье до победы

Сделать загрузчик канонического JSON, GameSession, базовые словари, `add/combine/mutate/run`, простые терминал и досье, таймер проверки, экран успеха, main scene.

Выход: контрольная сессия из спецификации проходит через UI. Результат — 1 попытка, Exposure 10. Уже на этом этапе исключить блокирующий перебор и зависимость доменной логики от UI.

### B. Полные правила и ошибки

Добавить оставшиеся команды, валидацию синтаксиса/данных, атомарные лимиты, повторные запуски, два вида провала, приоритет результатов, чистый restart, безопасный вывод текста.

Выход: тесты доменных правил и CLI проходят; ошибки не портят сессию; провал не вызывает автоматический перезапуск.

### C. Удобство и объяснимость

Добавить историю/черновик, Tab, help, preview с прогнозом, просмотр словарей, понятные статусы, маркер подсказки, объяснение на победе, адаптацию к минимальному окну.

Выход: пользователь без знания ответа может понять доступные операции и вывести гипотезу из досье. Это проверить отдельно плейтестом, не заменять автотестом.

### D. Атмосфера и сдача

Тема, кириллица, необязательные слабые эффекты, звук, настройки, attribution для добавленных ассетов. Затем чистый запуск, проверка консоли, ручной UI smoke test.

Выход: готовый цикл без ошибок; README с запуском и проверками; отчёт о проверке с фактическими результатами. Не откладывать работоспособность ради CRT-шейдера.

## 3. Автоматические проверки

Использовать имеющийся тестовый подход проекта; если его нет — лёгкий GDScript runner без обязательного внешнего framework. Runner обязан завершаться ненулевым кодом при провале. Ниже проверки требуемого поведения, а не привязка к внутренним классам.

### CLI и словари

| ID | Сценарий | Ожидание |
|---|---|---|
| C01 | `hashdog add "two words"` | Один элемент `two words` в words |
| C02 | Незакрытая кавычка, неизвестный флаг, повтор флага, недостающее значение | Ошибка; все данные и ресурсы прежние |
| C03 | Повтор `add Barsik`, затем `add barsik` | `[Barsik, barsik]`, порядок сохранён |
| C04 | `[Barsik, Lexa] × [1990, 2010]` | Четыре значения в порядке из спецификации |
| C05 | combine с назначением, равным источнику | Результат построен по прежним снимкам |
| C06 | mutate Barsik1990 всеми тремя правилами | Только `B@rsik1990!`; исходный вариант не сохраняется |
| C07 | Перестановка флагов mutate | Тот же результат; правила идут в фиксированном порядке |
| C08 | Два значения после мутации совпали | Один результат, первое положение сохранено |
| C09 | 101 уникальный результат или строка длиннее 64 | Ошибка без частичной записи |
| C10 | Неизвестный словарь; создание 17-го; пустой источник combine | Понятная ошибка, состояние прежнее |
| C11 | reset / remove | Меняют только выбранный словарь; ресурсы прежние |
| C12 | `hashdog add "--leet"`, экранированные кавычки/слеши | Буквальные аргументы по грамматике |
| C13 | `hashdog mutate candidates` без правил | Ошибка, не скрытый no-op |
| C14 | Каноническая цепочка команд | Ровно один правильный кандидат и успешная атака |

### Ресурсы и сессия

| ID | Сценарий | Ожидание |
|---|---|---|
| S01 | Новая миссия | READY, 10 попыток доступны, Exposure 0, четыре пустых словаря |
| S02 | Пустой run | Ошибка; нет +10, нет таймера |
| S03 | Верный первый кандидат | WON, attempts_used=1, Exposure=10 |
| S04 | Один промах, очередь закончилась | READY, attempts_used=1, Exposure=15 |
| S05 | После S04 запустить правильный новый кандидат | WON, attempts_used=2, Exposure=25 |
| S06 | Один run: 9 промахов, затем правильный | WON, attempts_used=10, Exposure=55 |
| S07 | Один run: 10 промахов | LOST/RATE_LIMIT, attempts_used=10, Exposure=60 |
| S08 | 6 отдельных run по одному промаху | READY, attempts_used=6, Exposure=90 |
| S09 | После S08 ещё один непустой run | LOST/TRACE, Exposure=100; attempts_used всё ещё 6 |
| S10 | Фикстура READY, attempts_used=9, Exposure=85; run с промахом | После цены run 95, после промаха 100; LOST/TRACE, attempts_used=10 |
| S11 | Фикстура как S10, кандидат правильный | WON, attempts_used=10, Exposure=95 |
| S12 | run/мутация/клик факта во время RUNNING | Отклонены; очередь, ресурсы и словари не изменились |
| S13 | preview/help/list/clear во время RUNNING | Атака продолжается, ресурсы не меняются от этих команд |
| S14 | Перезапуск и срабатывание старого callback | Новая миссия остаётся в начальном состоянии |
| S15 | Повтор run с ранее неверным словом | Снова расходует попытку и Exposure |
| S16 | Продолжение тиков после WON/LOST | Никаких новых проверок или повторных итоговых событий |
| S17 | 4 отдельных run по одному промаху | Exposure=60, сессия READY, одна подсказка; следующий порог не повторяет её |
| S18 | Порог подсказки достигнут на проигрышном шаге | Подсказки поверх результата нет |
| S19 | preview при READY, Exposure=85, осталось 10, очередь 3 слова | Цена run 10; при всех промахах проверится 1 слово, затем TRACE; секрет не используется |

S10/S11 — специально заданные пограничные состояния, не обещание конкретного игрового маршрута до них.

### Данные

- Канонический JSON загружается; контрольный маршрут действительно строит его пароль.
- Несуществующий файл, испорченный JSON, неизвестная версия, дубли ID, неверные типы, неверные ссылки solution: диагностическая ошибка вместо падения.
- Публичное представление досье не содержит solution; preview не меняется при подмене секрета в тестовой миссии.

## 4. Ручная приёмка

- [ ] Открыть проект установленным совместимым Godot; main scene запускается без агента.
- [ ] Пройти каноническую победу кликами фактов и CLI. Проверить итоговые числа.
- [ ] Получить RATE_LIMIT и TRACE обычными командами, прочитать различающиеся причины.
- [ ] После каждого результата повторить миссию; нет старых событий, словарей и ресурсов.
- [ ] Завершить очередь промахом при оставшихся ресурсах; подготовить и запустить новую гипотезу.
- [ ] Up/Down восстанавливают черновик; Tab работает по контексту и не мешает фокусу других элементов.
- [ ] Ошибочную команду можно исправить без повторного набора; текст в кавычках работает.
- [ ] Слова с кириллицей и текст вида `[color=red]` выводятся буквально, не меняют разметку журнала.
- [ ] Preview и панель словаря показывают фактический порядок проверки.
- [ ] При 1440×900 и 1024×720 доступны ввод, ресурсы, кнопки и прокрутка; длинные строки не ломают компоновку.
- [ ] Во время атаки окно отзывчиво, повторный Enter не запускает второй поток проверки.
- [ ] Подсказка появляется один раз, оставляет маркер, работает при выключенных эффектах.
- [ ] Mute и громкость действуют на всё аудио; restart сохраняет настройки.
- [ ] Игра работает при отсутствии необязательного музыкального файла.
- [ ] Консоль запуска и завершения не содержит ошибок GDScript/runtime и отсутствующих обязательных ресурсов.

Мини-плейтест новым игроком: выдать только встроенную памятку, не раскрывать пароль и контрольную цепочку. Записать длительность, непонятные команды, выбранные гипотезы и основания. Цель 5–10 минут — ориентир. Если решение воспринимается как произвольное угадывание, доработать факты/подсказки, не увеличивать случайно бюджет.

## 5. Команды проверки после реализации

Примеры, не утверждение об уже существующем runner. Агент должен указать фактический executable и созданный путь тестов в README.

```text
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/run_tests.gd
godot --path .
```

Headless проверяет импорт и логику, но не читаемость UI, звук и эффекты. Эти свойства проверять в окне. Если GUI-проверка или плейтест недоступны, оставить соответствующие пункты непроверенными и назвать это в отчёте.

## 6. Что исправлено относительно исходника

- Убрана двойственность «сгенерированная цель / генерация вне MVP»: первый сценарий авторский.
- Две несовместимые схемы JSON заменены одной; кириллические значения отделены от токенов.
- Определены источники, назначения, порядок, дедупликация и ограничения словарей.
- Мутации больше не создают необъявленные комбинации; пример сессии воспроизводим.
- Exposure не начисляется за локальный combine. Подсказка не требует ожидания 10–15 секунд в субсекундной атаке.
- Общий бюджет сохраняется между запусками; исчерпание очереди отделено от проигрыша.
- Определён приоритет одновременных событий, включая верную десятую попытку.
- Исправлена арифметика: по прежним правилам 7 проверок с 6 промахами стоили бы 40 Exposure без combine, а не 35. Новый канонический маршрут стоит 10.
- Удалены обязательные несуществующие интеграции, недостоверные обещания возможностей инструментов и преждевременные архитектурные подсистемы.
- Музыка и мемы отделены от работоспособности MVP; добавлены проверяемые критерии и честный статус тестирования.
