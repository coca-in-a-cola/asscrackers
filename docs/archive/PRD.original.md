# Техническое задание: MVP «Asscrackers» (нормальное название ещё не придумано)

**Проект:** Хакерский симулятор с процедурной генерацией головоломок на основе профилирования цели  
**Движок:** Godot (GDScript) 
**Инструменты разработки:** opencode + GPT-6.0 (через Godot MCP)  
**Цель документа:** Дать достаточную спецификацию для генерации работающего прототипа AI-агентом


## 1. Обзор проекта

### 1.1. Высокоуровневая концепция

Игрок — анонимус в киберпанк-мегаполисе. Через внутриигровое OSINT-приложение **«Глаз Бога» (G-d's Eye)** он собирает досье на цель: соцсети, утечки паролей, переписки, поисковые запросы. На основе досье игрок собирает словарь и запускает **словарную атаку** через терминал `hashdog` (в стиле hashcat). Цель — угадать пароль за минимальное число попыток, не превысив **Exposure** (уровень обнаружения) и **Rate-лимит** (пул попыток).

**Ключевое отличие от аналогов:** пароль генерируется не случайно, а на основе психологического профиля цели. Игрок должен думать не как переборщик, а как **профайлер**: «Что этот человек вставит в пароль?»

### 1.2. Референсы

| Референс | Что берём |
|-----------|-----------|
| **Breach Noir** | Механика Exposure, атмосфера детективного взлома |
| **Mr. Robot** | Визуальный стиль, нарратив «ненадёжного рассказчика» |
| **Yunyun Syndrome** | Структура UI, ощущение «рабочего стола хакера» |
| **hashcat** | Синтаксис команд, логика словарных атак и правил (rules) |
| **Kali Linux** | Эстетика рабочего стола, терминала, утилит |
| **White Bat Audio** | Музыкальное сопровождение (synthwave/darksynth) |

### 2.3. Роль AI-агентов в разработке

**opencode** — это AI-ассистент, подключаемый к Godot через **Godot MCP** (Model Context Protocol). Через `opencode.json` в корне проекта агент получает доступ к инструментам:

- **Инспекция сцен:** чтение дерева нод, свойств, скриптов
- **Мутация сцен:** создание нод, привязка скриптов, соединение сигналов (с поддержкой Undo)
- **Запуск и тестирование:** headless-запуск игры, снятие скриншотов, проверка на ошибки парсинга
- **Редактирование GDScript:** создание и правка скриптов с проверкой синтаксиса

**GPT-6.0 Astra** используется через **Playbot** (AI-IDE от Playco) или напрямую через API. Он подключается к Godot напрямую, позволяя модели редактировать сцены, запускать и тестировать игру, проверять изменения в реальном времени.

**Рекомендуемый workflow:**

1. Агент создаёт структуру папок и `project.godot` по спецификации.
2. Через MCP создаёт базовые сцены (`Desktop.tscn`, `Terminal.tscn`, `GdEye.tscn`).
3. Пишет GDScript-скрипты по разделам 4–6 этого ТЗ.
4. Запускает игру headless, проверяет логи на ошибки.
5. Итерирует: снимает скриншот, сравнивает с ожидаемым UI, правит.


## 3. MVP: Границы

### 3.1. Что входит в MVP

MVP — это **одна законченная сессия взлома**: от получения цели до успеха/провала.

| # | Фича | Описание |
|---|------|----------|
| **M1** | Терминал с автокомплитом | Ввод команд `hashdog`, стрелки для истории, Tab для дополнения |
| **M2** | Панель «Глаз Бога» | Отображение досье цели, клик по факту → добавление в словарь |
| **M3** | Словарная атака | Команды `add`, `mutate`, `combine`, `run` с визуализацией перебора |
| **M4** | Rate-лимит × ботнет | Пул попыток (10), каждая попытка = 1 токен |
| **M5** | Exposure | Параметр 0–100, растёт за попытки и шумные действия |
| **M6** | Киберпанк-UI | Тёмная тема, неон (циан/маджента), CRT-свечение, сканлайны |
| **M7** | Одна сгенерированная цель | JSON-профиль с фактами и паролем |
| **M8** | Глитч-подсказка | При Exposure > 60 правильное слово на секунду подсвечивается в досье |
| **M9** | Музыка | Один трек synthwave (White Bat Audio) на фоне |
| **M10** | Экран успеха/провала | «ACCESS GRANTED» / «TRACE DETECTED» с мемом |

### 3.2. Что НЕ входит в MVP (Post-MVP)

- Визуальная новелла / диалоги с заказчиками
- Встроенный браузер с «сайтами» (QuackQuackGo)
- Несколько источников информации (соцсети, переписки, метаданные)
- Процедурная генерация целей (в MVP — один или несколько захардкоженных JSON)
- Прогрессия, криптокредиты, магазин улучшений
- Сюжет, ветки, концовки
- Внутренний голос / альтер-эго Anonymous
- Информационный передоз
- Ежедневные вызовы


## 4. Детальная спецификация механик

### 4.1. Система фактов и генерация пароля

**Цель** — JSON-объект:

```json
{
  "id": "target_001",
  "name": "Алексей",
  "nickname": "Lexa",
  "age": 34,
  "city": "Пермь",
  "pet": "Барсик",
  "birth_year": 1990,
  "favorite_band": "Kino",
  "leaked_password": "fluffy2010",
  "password": "B@rsik1990!",
  "password_facts": ["pet", "birth_year"],
  "mutations": ["leet_a", "caps_first", "append_exclamation"]
}
```

**Генерация пароля (TargetGenerator.gd):**

1. Выбрать 2–3 факта с высоким весом (см. таблицу ниже).
2. Склеить их в базовую строку (например, `Barsik` + `1990` = `Barsik1990`).
3. Применить мутации:
   - `leet_a`: `a` → `@`
   - `caps_first`: первая буква заглавная
   - `append_exclamation`: добавить `!` в конец
   - `append_year`: добавить год
   - `reverse`: реверс строки

| Факт | Вес | Пример |
|------|-----|--------|
| Имя питомца | 0.9 | `Barsik` |
| Старый пароль из утечки | 0.95 | `fluffy2010` |
| Год рождения | 0.8 | `1990` |
| Никнейм | 0.7 | `Lexa` |
| Любимая группа | 0.5 | `Kino` |
| Город | 0.4 | `Perm` |

### 4.2. Терминал: команды

| Команда | Синтаксис | Описание |
|---------|-----------|----------|
| `add` | `hashdog add Barsik` | Добавить слово в словарь |
| `mutate` | `hashdog mutate --leet --caps --append "!"` | Применить мутации ко всему словарю |
| `combine` | `hashdog combine names years` | Склейка двух словарей |
| `preview` | `hashdog preview` | Показать размер словаря и预估 попыток |
| `run` | `hashdog run` | Запустить перебор |
| `clear` | `clear` | Очистить терминал |
| `help` | `help` | Список команд |

**Автокомплит:**

- При вводе `hashdog ` → всплывают подсказки `add`, `mutate`, `combine`, `run`.
- При вводе `--` → подсказки `--leet`, `--caps`, `--append`, `--prepend`, `--years`.
- Tab дополняет до ближайшего совпадения.
- Стрелки вверх/вниз — история команд.

### 4.3. Движок перебора (HashdogEngine.gd)

```
func run_attack(wordlist: Array, target_password: String, max_attempts: int) -> Dictionary:
    var attempts = 0
    var log = []
    for word in wordlist:
        if attempts >= max_attempts:
            return {"success": false, "reason": "rate_limit", "attempts": attempts}
        attempts += 1
        log.append("[+] Trying " + word + "...")
        if word == target_password:
            return {"success": true, "attempts": attempts, "log": log}
    return {"success": false, "reason": "not_found", "attempts": attempts, "log": log}
```

**Визуализация:** логи бегут строка за строкой с задержкой 50–100 мс. Прогресс-бар показывает `attempts / max_attempts`.

### 4.4. Rate-лимит и ботнет

- **Пул попыток:** `10` (базовое значение, в MVP — константа).
- Каждая попытка перебора тратит 1 токен.
- Если пул исчерпан до нахождения пароля — провал, миссия перезапускается.
- **Визуально:** в углу экрана — `BOTNET: ████████░░ 8/10`.

### 4.5. Exposure

- Начальное значение: `0`.
- `+5` за каждую неудачную попытку перебора.
- `+10` за команду `run` (факт запуска атаки).
- `+15` за `combine` (более агрессивная атака).
- При `Exposure >= 100` — мгновенный провал: `TRACE DETECTED`.
- **Визуально:** полоса в верхней части экрана, меняет цвет: зелёный → жёлтый → красный.

### 4.6. Глитч-подсказка

- При `Exposure > 60` и нахождении в панели «Глаз Бога»:
  - Раз в 10–15 секунд на 0.5 секунды правильное слово из пароля подсвечивается ярко-маджента в тексте досье.
  - Звук: резкий писк, шум.
- Это создаёт ощущение «шизофренического прозрения».

## 7. План разработки (для AI-агента)

## 8. Post-MVP: Дорожная карта

Ниже — фичи, которые **не входят в MVP**, но закладываются в архитектуру.

### 8.1. Расширение источников информации
- **Встроенный браузер:** открытие внутриигровых «сайтов» по URL. Поисковик **QuackQuackGo** (пародия на DuckDuckGo).
- **Соцсети:** страницы цели с постами, фото, лайками. Извлечение фактов.
- **Переписки:** фрагменты диалогов с друзьями, намёки на пароль.
- **Метаданные:** EXIF фото, геолокация, время активности.

### 8.2. Нарратив и персонажи
- **Визуальная новелла:** диалоги с заказчиками через мессенджер-интерфейс.
- **Альтер-эго Anonymous:** внутренний голос, комментирующий действия. Иногда даёт подсказки, иногда противоречит.
- **Сюжет:** цепочка заказов, ведущая к корпорации «Анус Индастриз».

### 8.3. Прогрессия и экономика
- **Криптокредиты:** валюта за успешные взломы.
- **Магазин:** покупка улучшений (больше попыток, меньше Exposure, новые правила мутаций).
- **Репутация:** открывает более сложные заказы.
- **Ежедневные вызовы:** сгенерированные цели с ограниченным временем.

### 8.4. Психологические механики
- **Информационный передоз:** при долгом изучении досье экран «плывёт», появляются артефакты.
- **Глюки как подсказки:** усиление механики из MVP — при высоком стрессе игрок видит фрагменты пароля в случайных местах.
- **Ненадёжный рассказчик:** Anonymous иногда врёт, игрок должен решать, кому верить.

### 8.5. Процедурная генерация
- **Генератор целей:** случайные имена, города, питомцы, увлечения, утечки.
- **Генератор паролей:** на основе весов фактов и пула мутаций.
- **Seed:** воспроизводимость для ежедневных вызовов.
