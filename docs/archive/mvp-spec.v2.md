# MVP: нормативная спецификация (архив v2, заменён после плейтеста)

Связанный продуктовый документ: [PRD](../PRD.MD). Числа ниже — стартовый баланс, не результаты плейтеста.

## 1. Модель симуляции

`hashdog` — вымышленный клиент проверки паролей удалённого сервиса. Это объясняет расход попыток и обнаружение. Реализация целиком локальная: сравнение строк с паролем миссии. Не эмулировать настоящий offline hashcat, где сетевой rate limit был бы нелогичен.

Сессия хранит:
- `phase`: `READY`, `RUNNING`, `WON`, `LOST`.
- `attempts_used`: 0–10, не обнуляется между запусками.
- `exposure`: 0–100, не уменьшается во время миссии.
- Именованные словари, активный снимок очереди, индекс текущего запуска.
- Журнал попыток текущей миссии и результат `SUCCESS`, `RATE_LIMIT`, `TRACE` либо отсутствие результата.
- `hint_shown`: однократность подсказки.

Начальные словари: `words`, `names`, `years`, `candidates`; все пустые. `words` — назначения ручного `add` по умолчанию; `candidates` — очередь `run` по умолчанию. Словари не объединяются автоматически.

## 2. Ресурсы и переходы состояний

| Действие | Попытки | Exposure |
|---|---:|---:|
| Читать досье, редактировать/комбинировать словари, preview, help | 0 | 0 |
| Принятый `run` непустого словаря | 0 | +10 |
| Проверить неверный кандидат | 1 | +5 |
| Проверить верный кандидат | 1 | 0 |
| Ошибка команды, пустой run, повторный run в RUNNING | 0 | 0 |

Порядок принятого `run`:
1. Проверить `READY`, существование и непустоту словаря. Ошибка не меняет сессию.
2. Создать неизменяемый снимок очереди, прибавить 10 Exposure.
3. Если Exposure ≥ 100: `LOST/TRACE`, ни одного кандидата не проверять.
4. Иначе `RUNNING`. Первая проверка через 350 мс, последующие с тем же интервалом.
5. На каждой проверке сначала потратить одну попытку, затем сравнить строки строго с учётом регистра.
6. Совпадение → `WON/SUCCESS`, в том числе на десятой попытке.
7. Промах → +5 Exposure; затем проверить `TRACE`, затем `RATE_LIMIT`.
8. Если оба лимита достигнуты одним промахом, основной результат `TRACE`; итоговый экран показывает оба исчерпанных ресурса.
9. Если лимиты не достигнуты и очередь закончилась: вернуться в `READY`, вывести `NO MATCH — измените гипотезу`. Это не проигрыш.
10. Иначе продолжить очередь.

Exposure ограничивать сверху 100. После любого терминального результата дальнейшие проверки запрещены. Выдавать ровно один результат.

Во время `RUNNING` запрещены все изменения словарей и клики добавления фактов. `help`, `clear`, `hashdog list`, `hashdog preview` разрешены. Команду остановки в MVP не вводить. Повторный запуск заново проверяет выбранный словарь, включая уже проверенные ранее слова: автоматического пропуска нет, ресурс снова расходуется.

В `WON/LOST` доступны чтение журнала, help и кнопка перезапуска; команды изменения/запуска отклоняются. `clear` очищает только видимый журнал терминала, не статистику и не данные сессии.

Перезапуск — явная кнопка на итоговом экране. Сбрасывает ресурсы, словари, журнал, историю ввода, подсказку, текущую очередь и таймеры. Загружает ту же миссию. Отложенные callback предыдущей сессии не могут изменить новую: отмена таймера плюс идентификатор поколения сессии или эквивалентная защита.

## 3. Словари и преобразования

Словарь — упорядоченный список уникальных строк. Порядок вставки сохраняется, равенство регистрозависимое. Лимиты: 100 кандидатов в словаре, 64 Unicode-символа в кандидате, 16 словарей с учётом четырёх начальных. Пустые строки запрещены.

Имена словарей: `[a-z][a-z0-9_]{0,23}`. Отсутствующий словарь разрешено создать через `add --to`, `combine --out` или `mutate --out`; остальные операции требуют существующий.

Все изменения атомарны: сначала рассчитать результат и проверить лимиты, затем применить. Ошибка не оставляет частичного словаря. Дедупликация — до проверки количества; первый экземпляр сохраняется. Не обрезать результат молча.

`combine`: декартово произведение, без разделителя, сначала внешний цикл по левому словарю, внутри — по правому. `[Barsik, Lexa] × [1990, 2010]` → `[Barsik1990, Barsik2010, Lexa1990, Lexa2010]`. Выход заменяет содержимое назначения, а не дописывает. Назначение может совпадать с источником: сначала снять оба снимка. Пустой источник — ошибка.

`mutate`: ровно один результат на исходную строку до дедупликации; исходные варианты не добавляются автоматически. Мутации не склеивают элементы и не генерируют все подмножества правил.

Порядок применения фиксирован, независимо от порядка флагов:
1. `--caps`: если первый символ — ASCII `a`–`z`, перевести его в верхний регистр; остальное не менять.
2. `--leet`: заменить все строчные `a` на `@`; другие символы не менять.
3. `--append TEXT`: дописать непустой TEXT.

Этот ограниченный leet описать прямо в help. `--prepend`, `--years`, reverse и дополнительные таблицы leet пока не поддерживаются. `mutate` без флагов преобразования — ошибка. Без `--out` заменяет исходный словарь; с `--out` заменяет назначение, источник сохраняет.

Ручной ввод не транслитерируется и не меняет регистр. Досье задаёт явные ASCII-токены для русскоязычных фактов; игрок видит соответствие «Барсик → Barsik» до добавления.

## 4. CLI: полная грамматика MVP

```text
help
help hashdog
clear
hashdog add WORD [--to DICT]
hashdog remove WORD [--from DICT]
hashdog list
hashdog list DICT
hashdog reset DICT
hashdog combine LEFT RIGHT --out DICT
hashdog mutate DICT [--caps] [--leet] [--append TEXT] [--out DICT]
hashdog preview [DICT]
hashdog run [DICT]
```

- `add`: без `--to` использует `words`; существующее слово — сообщение «уже есть», без изменения порядка.
- `remove`: без `--from` использует `words`; отсутствующее слово — сообщение «не найдено», без изменений.
- `list`: имена и размеры всех словарей; с именем — все элементы по порядку с индексами от 1.
- `reset`: очищает словарь, не удаляет имя. Не перезапускает миссию.
- `preview/run`: без имени используют `candidates`.
- `preview`: показывает всю очередь с индексами, размер, оставшиеся попытки, цену запуска и прогноз ресурсов при последовательных промахах. Прогноз рассчитывается теми же правилами лимитов, без чтения секретного пароля. Предупреждает, если все элементы не успеют провериться; запуск не запрещает.
- Пустой `preview` допустим; пустой `run` — ошибка без цены.

Парсер:
- Команды, флаги и имена словарей регистрозависимы.
- Пробелы/табуляции вне кавычек разделяют аргументы, начальные/конечные игнорируются.
- Одинарные и двойные кавычки группируют аргумент; сами не входят в значение. Пробелы внутри сохраняются.
- Внутри кавычек `\\` означает обратный слеш; слеш перед текущим типом кавычки экранирует её. Другие escape-последовательности — ошибка. Вне кавычек слеш — обычный символ.
- Кавычки охватывают целый токен; смешивание `ab"cd"` — ошибка. Незакрытые кавычки — ошибка.
- Позиционные аргументы идут до флагов; флаги после них допускаются в любом порядке. Повтор любого флага — ошибка.
- Значение флага — следующий токен. Токен, начинающийся с `--`, как буквальное значение должен быть в кавычках; парсер сохраняет признак цитирования.
- Лишние аргументы, неизвестные команды/флаги, недостающие значения — ошибка с короткой корректной формой команды. Никаких побочных действий.
- Лимит строки ввода — 512 символов; пустой Enter ничего не выполняет и не сохраняет в истории.
- Это не shell: нет pipe, выполнения программ, чтения файлов по пользовательским путям и интерполяции переменных.

UI-клик вызывает тот же обработчик добавления, что CLI, с готовыми аргументами; не собирает исполняемую строку из произвольного текста. Журнал может показать эквивалент команды. Пользовательский текст выводить буквально, не интерпретировать как BBCode.

### История и Tab

История хранит последние 100 непустых введённых строк, включая ошибочные; соседние одинаковые строки не дублируются. Up идёт к старым, Down — к новым; при первом Up сохранить текущий черновик, после последней записи Down вернуть его. Клики фактов в историю ввода не попадают.

Tab работает при курсоре в конце строки вне кавычек: дополняет текущий токен по контексту. Поддержать корневые команды, подкоманды `hashdog`, флаги допустимой команды, имена существующих словарей в соответствующих позициях. Не предлагать секретные данные и значения фактов. При одном совпадении — дополнить и добавить пробел; при нескольких — показать список и дополнить общий префикс, повторный Tab перебирает совпадения лексикографически. Новое редактирование сбрасывает цикл. Внутри кавычек/в середине строки Tab не меняет текст. За пределами терминального ввода Tab сохраняет обычную навигацию фокуса.

## 5. Миссия и разрешимость

В MVP нет случайного выбора пароля. Миссия должна давать основания для каждой части и каждого преобразования. «Психологический профиль» выражается фактами и привычками, не скрытыми коэффициентами.

Файл `data/targets/target_001.json` — источник авторских текстов миссии. Ниже минимальный пример той же схемы и контрольного решения; в игре формулировки расширены под ANUS INDUSTRIES, абсурд и чёрный юмор:

```json
{
  "schema_version": 1,
  "id": "target_001",
  "display_name": "Алексей «Lexa»",
  "brief": "Заказ: получить доступ к учебному архиву цели. Изучи досье и проверь гипотезу пароля.",
  "facts": [
    {"id": "pet", "label": "Кот", "value": "Барсик", "token": "Barsik", "dictionary": "names", "source": "Профиль", "note": "Все важные аккаунты называет в честь кота."},
    {"id": "birth_year", "label": "Год рождения", "value": "1990", "token": "1990", "dictionary": "years", "source": "Анкета", "note": "В памятных комбинациях использует полный год своего рождения."},
    {"id": "nickname", "label": "Никнейм", "value": "Lexa", "token": "Lexa", "dictionary": "names", "source": "Профиль", "note": "Публичный псевдоним."},
    {"id": "leaked", "label": "Старый пароль", "value": "Fluffy2010!", "token": "Fluffy2010!", "dictionary": "words", "source": "Учебная утечка", "note": "Слово с заглавной буквы, затем год и восклицательный знак."},
    {"id": "habit", "label": "Заметка", "value": "Теперь меняю маленькую a на @. Порядок: сначала имя, потом год; ! оставляю в конце.", "token": null, "dictionary": null, "source": "Фрагмент переписки", "note": "Привычка менять старый шаблон вместо выбора нового."}
  ],
  "solution": {
    "password": "B@rsik1990!",
    "fact_ids": ["pet", "birth_year"],
    "hint_fact_id": "pet",
    "explanation": "Имя кота + год рождения; заглавная первая буква, a → @, затем !."
  }
}
```

`source` — подпись происхождения в едином досье, не отдельное приложение или механика сбора. Не выводить возраст, зависящий от текущей даты.

Валидация загрузки:
- Поддерживаемая `schema_version`, непустые строковые `id`, `display_name`, `brief`, массив фактов, объект solution.
- Уникальные непустые `facts[].id`; `label/value/source/note` — строки, `label/value` непустые.
- Для добавляемого факта `token` — допустимый кандидат, `dictionary` — одно из четырёх начальных имён. Для информационного оба поля `null`.
- `solution.password` — допустимый кандидат; `fact_ids` — непустой массив уникальных существующих ID добавляемых фактов; `hint_fact_id` входит в него; explanation — непустая строка.
- Неизвестные дополнительные поля игнорировать; неизвестную версию отклонять.
- При ошибке данных показать отдельный экран ошибки с путём файла и причиной, не запускать частично инициализированную миссию.

UI получает публичное досье без `solution`. Проверка и подсказка используют внутренние данные сессии. До успеха пароль и объяснение не выводятся в UI/журнал. Это разделение представлений, не защита локального JSON от просмотра игроком.

### Контрольная успешная сессия

```text
hashdog add Barsik --to names
hashdog add 1990 --to years
hashdog combine names years --out candidates
hashdog mutate candidates --caps --leet --append "!"
hashdog preview
hashdog run
```

Очередь: ровно `[B@rsik1990!]`. Результат: успех, использована 1 попытка, осталось 9, Exposure 10. Те же первые два действия доступны кликами по фактам.

Игрок вправе ввести готовый пароль вручную. Это ожидаемо для терминальной игры. Одна статическая миссия не обещает реиграбельность после знакомства с ответом.

## 6. Глитч-подсказка

Если сессия ещё активна, Exposure ≥ 60 и подсказка ещё не показывалась, подсветить факт `hint_fact_id` на 0.5 секунды, пометить `hint_shown`. Проверять после изменений Exposure, но после проверки терминального результата: на экране поражения подсказку не запускать.

Подсветка указывает важный факт, не показывает готовый пароль. Панель досье постоянно видима, поэтому условие «игрок открыл приложение» не требуется. После краткой анимации оставить статический маркер «Зацепка», доступный до конца миссии. Если факт вне видимой области, показать также уведомление с его названием. Подсказка не приостанавливает очередь.

При отключённых эффектах использовать маркер без вспышки и RGB-сдвига. Подсказка не должна быть обязательной для решения.

## 7. UI и обратная связь

Основной экран — Control с контейнерной компоновкой:
1. Верхняя строка: название миссии, Exposure `N/100`, `BOTNET: N/10` (оставшиеся попытки), состояние.
2. Слева ~60% ширины: прокручиваемый журнал и строка ввода.
3. Справа ~40%: прокручиваемое досье и компактный просмотр выбранного словаря с количеством и порядком кандидатов.
4. Нижняя строка: краткий help, переключатель эффектов, mute и громкость.

Стартовое окно 1440×900, минимум 1024×720. При обоих размерах строка ввода и ресурсы видимы, длинный контент прокручивается, текст не перекрывает кнопки. Для читаемости текст сохраняет размер при изменении окна: stretch отключён, компоновка адаптируется контейнерами. Не полагаться на абсолютные координаты основных панелей.

Факт показывает значение, источник, заметку и кнопку «Добавить → names/years/words». Для информационных фактов кнопки нет. Добавление подтверждается именем словаря и словом, дубликат — отдельным нейтральным сообщением. После клика фокус возвращается в терминал.

Прогресс атаки — `проверено в запуске / размер снимка очереди`. Бюджет миссии показывается отдельно: попытки текущего запуска нельзя смешивать с общим ресурсом.

Ошибки команд не уничтожают ввод: сохранять строку для исправления. Успешно принятую команду добавлять в журнал и очищать ввод. Видимый журнал ограничить последними 1000 строками; автопрокрутка только если игрок уже внизу. Историю результатов попыток хранить независимо от очистки журнала.

Итоговый экран:
- `ACCESS GRANTED`: найденный пароль, объяснение, потраченные/оставшиеся попытки, Exposure.
- `RATE LIMIT EXCEEDED`: исчерпан бюджет; пароль не раскрывать.
- `TRACE DETECTED`: достигнут Exposure; пароль не раскрывать.
- На всех: причина, статистика и «Повторить миссию». Нет автоматического сброса до прочтения результата.

Стиль: фон `#0a0a0f`, основной акцент `#00ffcc`, вторичный `#ff00aa`, предупреждение `#ffff00`. Основной длинный текст может быть светло-серым для читаемости. Моноширинный шрифт с кириллицей; системный/движковый fallback обязателен. Размер основного текста ориентировочно 18 px при базовом окне, проверить минимальное.

Exposure: <40 — спокойный, 40–69 — предупреждение, ≥70 — опасность. Цвет всегда дублируется числом/текстом. Сканлайны слабые, глитч локальный. Не предписывать `CanvasModulate` как механизм свечения: выбрать реально работающий с Compatibility способ. Декоративный слой не перехватывает мышь. Переключатель эффектов отключает сканлайны, вспышки и сдвиги, сохраняя информацию.

Звук: добавление, запуск, успех, провал; глитч тихий. Клавиатурный click необязателен. Отсутствие музыки не ломает игру. Для каждого стороннего ассета записать происхождение, лицензию/условия и attribution в `assets/ATTRIBUTION.md` при его добавлении. White Bat Audio — ориентир звучания, не автоматически разрешённый обязательный файл. Настройки аудио и эффектов сохраняются при повторе миссии, но не обязаны переживать выход из приложения.

## 8. Архитектурные границы

Предлагаемая структура; небольшие изменения допустимы при сохранении ответственности:

```text
data/targets/target_001.json
scenes/main.tscn
scenes/ui/terminal.tscn
scenes/ui/dossier_panel.tscn
scenes/ui/result_panel.tscn
scripts/domain/mission_loader.gd
scripts/domain/dictionary_service.gd
scripts/domain/attack_engine.gd
scripts/domain/game_session.gd
scripts/terminal/command_parser.gd
scripts/terminal/command_dispatcher.gd
scripts/terminal/autocomplete.gd
scripts/ui/...
assets/...
tests/...
```

- `MissionLoader`: загрузка/валидация JSON, выдача публичных и внутренних данных.
- `CommandParser`: чистое преобразование строки в структурированную команду либо ошибку; не меняет игру.
- `CommandDispatcher`: семантическая проверка команды и вызов сценария сессии. Общая точка для CLI и UI.
- `DictionaryService`: упорядоченные словари, снимки, атомарные операции и лимиты. Не знает пароль и Exposure.
- `AttackEngine`: детерминированный шаг сравнения и расчёт ресурсов. Не зависит от Control, реального времени и файловой системы.
- `GameSession`: владеет состоянием, словарями, таймером и поколением сессии; единственный источник ресурсов/результата.
- UI: представление, ввод, эффекты. Обновляется через сигналы/структурированные результаты, не вычисляет баланс самостоятельно.

Таймер задаёт темп, но не определяет бизнес-правила. Тесты двигают атаку шагами без реального ожидания. Не использовать блокирующие циклы с задержкой главного потока. Избежать глобальных autoload, если хватает владельца `Main`; не добавлять `TargetGenerator`, пока генерации нет в scope.

Ошибки парсинга, данных, состояния и лимитов различать. Пользовательские ошибки обрабатываются в UI без stack trace; ошибки реализации фиксируются в логах и исправляются.
